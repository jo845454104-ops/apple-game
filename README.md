# 🍎 사과게임 (DSA 아카데미 대회용)

일본 게임사이엔(ゲーム菜園)의 "사과게임"을 그대로 재현한 웹 게임입니다.
17×10(170개) 사과 중 드래그로 합이 10이 되는 사과들을 골라 터뜨리고, 2분 동안 최대한 높은 점수를 얻는 것이 목표입니다.

## 실행 방법

별도 빌드 없이 정적 파일만으로 동작합니다.

```bash
cd apple-game
python3 -m http.server 8080
```

브라우저에서 `http://localhost:8080` 접속. (또는 VSCode Live Server 등 아무 정적 서버 사용 가능)

## 게임 방법

- 마우스/터치로 드래그하면 선택 박스가 나타납니다.
- 박스 안에 걸친 사과들의 합이 10이 되면 박스와 사과가 빨갛게 변합니다.
- 그 상태로 드래그를 놓으면 사과가 사라지고 개당 1점을 얻습니다.
- 제한 시간 2분 안에 최대한 많은 점수를 모으세요. (전부 클리어하면 걸린 시간이 표시됩니다)
- 우측 하단 `연한 색` 체크박스로 사과 채도를 낮출 수 있고, `BGM` 체크박스로 배경음을 켤 수 있습니다.
- 우측 하단 `🌙 다크모드` 버튼으로 밝은 화면과 어두운 화면을 전환할 수 있습니다. 선택은 브라우저에 저장되어 다음 접속에도 유지되고, 한 번도 고르지 않았다면 운영체제의 다크모드 설정을 그대로 따릅니다.

## 실시간 접속자 수 · 채팅

화면 오른쪽에 채팅창이 붙어 있고, 상단 HUD에 현재 접속자 수가 표시됩니다.

- **채팅 기록은 서버에 남습니다.** 나중에 들어온 사람도 이전 대화를 볼 수 있고, 최근 100개를 불러옵니다.
- **대화가 쌓여도 게임판이 밀리지 않습니다.** 채팅 패널 높이가 게임판에 맞춰 고정되어 있고, 넘치는 대화는 패널 안에서 스크롤됩니다.
- **오래된 대화는 자동으로 정리됩니다.** 올라온 지 2시간이 지난 메시지는 개수와 상관없이 지워지고, 대화가 100개를 넘으면 오래된 것부터 지워져 100개만 남습니다. 다만 삭제는 올라온 지 2분이 지난 메시지에만 허용해서, 진행 중인 대화를 누군가 지워버리는 일은 생기지 않습니다.
- **닉네임은 한 번 정하면 변경할 수 없습니다.** 혼자서 여러 사람인 척하는 자작극을 막기 위한 제한입니다. 브라우저에 저장되므로(`localStorage`) 새로고침하거나 창을 닫았다 열어도 그대로 유지되고, 설정 화면에 변경 불가 안내가 표시됩니다.
- **채팅 닉네임이 랭킹 이름으로 그대로 쓰입니다.** 게임이 끝나면 이름을 다시 입력할 필요 없이 정해둔 닉네임으로 바로 등록됩니다. 닉네임을 아직 정하지 않았다면 등록 화면에서 정할 수 있고, 그 값이 채팅에도 함께 적용됩니다.
- 접속자 수는 각 참가자가 30초마다 보내는 신호를 15초 주기로 집계합니다. 실시간 리스너를 쓰면 읽기 횟수가 접속자 수의 제곱으로 늘어나 무료 한도를 넘기 때문에, 카운터만 주기적으로 갱신하는 방식을 택했습니다.
- 접속자 식별용 ID도 브라우저에 저장해 재사용합니다. 이렇게 하지 않으면 새로고침할 때마다 새 ID가 발급돼 같은 사람이 여러 명으로 집계됩니다.

> 브라우저 데이터를 지우거나 시크릿 창을 쓰면 닉네임과 식별 ID가 초기화됩니다. 서버 없이 브라우저만으로는 사용자 IP를 알 수 없어, 브라우저 단위 식별이 실질적인 최선입니다.

## 부정행위 방지

브라우저에서 실행되는 게임은 원리상 완벽한 조작 방지가 불가능합니다. 개발자도구를 열 수 있는 사람은 언제든 내부 함수를 직접 호출할 수 있기 때문입니다. 대신 **서버 규칙으로 걸러낼 수 있는 것은 최대한 걸러내고, 걸러지지 않는 조작은 기록에 흔적이 남도록** 설계했습니다.

[firestore.rules](firestore.rules)에서 검증하는 항목입니다. 클라이언트 코드를 우회해 Firestore에 직접 써도 아래 조건을 어기면 거부됩니다.

- 점수는 0~170 범위 (전체 사과 수를 넘을 수 없음)
- 매칭 횟수와 점수의 관계가 성립해야 함 (한 번에 지울 수 있는 사과는 2~10개이므로 `매칭×2 ≤ 점수 ≤ 매칭×10`)
- 플레이 시간이 2분 5초 이내이고, 사과 한 개당 최소 0.15초 이상 (만점이면 최소 25.5초)
- 등록 시각은 서버 시각만 허용 (과거·미래 시각 위조 차단)
- 정해진 필드 외 추가 필드 금지
- **등록된 점수의 수정·삭제 전면 차단** (남의 점수를 지우거나 자기 점수를 올릴 수 없음)
- 채팅은 수정 불가, 삭제는 2분이 지난 메시지에 한해 허용 (오래된 대화 자동 정리용)

점수 등록 시에는 화면에 표시된 점수 변수가 아니라 실제로 사라진 사과 개수를 다시 세어 전송합니다.

### 조작 감지 시 조치

서버가 기록을 거부하면 그 즉시 화면 전체가 잠기고 "부정 행위가 감지되었습니다" 안내가 뜹니다. 게임을 다시 시작할 수 없고, 차단 사실은 브라우저와 **서버 양쪽에 기기 ID로 기록**됩니다. 브라우저 저장소를 지우고 다시 들어와도 서버 기록을 확인해 계속 차단됩니다.

차단을 풀려면 운영자가 Firestore의 `blocked` 컬렉션에서 해당 문서를 지우면 됩니다.

```bash
npx firebase-tools firestore:delete blocked/<기기ID> --force --project jo8454-ea749
```

> 남는 위험: 실제 페이지에서 개발자도구로 게임 내부를 조작해 "그럴듯한" 기록(예: 120초에 150점, 매칭 60회)을 만들면 서버는 진위를 알 수 없습니다. 시크릿 창이나 다른 기기를 쓰면 차단도 우회됩니다. 상위권 시상이 걸린 대회라면 최종 순위는 현장에서 재플레이로 확인하는 것을 권합니다.

## 봇·도배 차단 (App Check)

파이썬 스크립트 같은 자동화 도구는 브라우저를 거치지 않고 Firestore에 직접 요청을 보냅니다.
이런 요청은 클라이언트 측 방어(전송 간격 제한, 도배 패턴 검사)를 전부 건너뛰기 때문에,
**App Check**로 "진짜 우리 웹페이지에서 온 요청"임을 증명하게 하는 것이 유일한 근본 대책입니다.

설정하면 스크립트는 토큰을 만들 수 없어 요청 자체가 거부됩니다. 설정 순서는 다음과 같습니다.

1. https://www.google.com/recaptcha/admin/create 에서 **reCAPTCHA v3** 사이트 등록
   - 라벨: 아무 이름
   - 유형: **점수 기반 (v3)**
   - 도메인: `jo845454104-ops.github.io`
   - 등록 후 나오는 **사이트 키**를 복사
2. Firebase 콘솔 → 빌드 → **App Check** → 앱 등록 → reCAPTCHA v3 선택 → 위 **비밀 키** 입력
3. App Check 화면의 **Cloud Firestore** 항목에서 **적용(Enforce)** 켜기
4. 이 저장소의 `firebase-config.js`에서 `recaptchaSiteKey` 에 1번의 사이트 키를 넣고 푸시

> 3번(적용)을 켜기 전에 4번을 먼저 배포하세요. 순서를 바꾸면 참가자 요청이 전부 거부됩니다.
> 코드는 이미 준비되어 있어 사이트 키만 넣으면 자동으로 켜집니다.

## 돌발 이벤트

평일 한국시간 **14:00~17:00 사이에 하루 1~2회**, 30분짜리 돌발 이벤트가 열립니다.
그 시간 안에 **목표 점수(107~112점, 회차마다 다름)** 를 넘기면 즉시 커피가 당첨됩니다.

일정은 예약 작업 없이 **날짜에서 계산**됩니다. 같은 날이면 누구 화면에서든 같은 시각·같은 목표가 나오므로
서버 없이도 모든 참가자가 동일한 이벤트를 봅니다. 주말에는 열리지 않습니다.

- 화면 상단에 배너가 뜨고 남은 시간이 초 단위로 표시됩니다 (예정일 때는 회색, 진행 중일 때는 빨간색)
- 이벤트당 닉네임 1개는 한 번만 받을 수 있습니다 (문서 ID를 `닉네임__이벤트`로 고정)
- 서버 규칙이 **평일 14~17시, 107점 이상, 본인 닉네임**인지 직접 검증합니다

## 닉네임 규칙

한국어 비속어와 혐오 표현이 들어간 닉네임은 사용할 수 없습니다. 목록은 [profanity.js](profanity.js)에 있고, 같은 내용이 [firestore.rules](firestore.rules)에도 들어가 있어 클라이언트를 우회해도 서버가 거부합니다. 사이에 공백이나 기호를 끼워 넣는 우회(`시 발`, `씨@발`)도 걸러집니다.

이미 금지어가 든 닉네임을 쓰던 사람은 다음 접속 때 닉네임이 자동으로 초기화되어 새로 정해야 합니다.

**채팅 내용에는 필터를 적용하지 않습니다.** 걸러지는 것은 닉네임뿐입니다.

## 온라인 랭킹(리더보드)

Firebase Firestore 기반의 **온라인 공유 랭킹**이 이미 연결되어 있습니다.
게임이 끝나면 닉네임을 입력해 등록할 수 있고, 상단 `🏆 랭킹` 버튼으로 모든 참가자의 상위 10위를 볼 수 있습니다.

**랭킹은 매일 오후 6시(한국시간)에 초기화됩니다.** 룰렛 횟수도 같은 시각에 초기화됩니다. 기록을 실제로 지우는 대신 직전 5시 30분 이후에 등록된 기록만 보여주는 방식이라, 예약 작업(Cloud Functions·유료 요금제)이 필요 없고 초기화가 누락될 일도 없습니다. 지난 기록은 데이터베이스에 그대로 남아 있어 나중에 확인할 수 있습니다.

- 프로젝트: `jo8454-ea749` (리전: asia-northeast3 / 서울)
- 컬렉션: `scores` (필드: `name`, `score`, `clears`, `durationMs`, `createdAt`), `messages`, `meta/presence`
- 보안 규칙: [firestore.rules](firestore.rules) — 누구나 읽기/등록 가능하되, 닉네임 1~12자·점수 0~170 범위를 검증하고 **수정과 삭제는 차단**합니다.

규칙을 수정했다면 아래 명령으로 다시 배포하세요.

```bash
npx firebase-tools deploy --only firestore:rules --project jo8454-ea749
```

`firebase-config.js`의 값을 플레이스홀더(`YOUR_...`)로 되돌리면 서버 없이 로컬(localStorage) 랭킹으로 자동 전환됩니다.

> 참고: 웹 클라이언트의 `apiKey`는 비밀값이 아니라 프로젝트 식별자라 공개 저장소에 포함되어도 무방합니다. 실제 접근 통제는 위 보안 규칙이 담당합니다.

## 파일 구조

- `index.html` — 마크업
- `style.css` — 원본과 동일한 초록 프레임 + 17×10 그리드 스타일
- `script.js` — 게임 로직 (드래그 선택, 합 판정, 타이머)
- `firebase-config.js` — Firebase 프로젝트 설정
- `firebase-app.js` — Firebase 앱 초기화 (leaderboard와 chat이 공유)
- `leaderboard.js` — 점수 등록/조회, 일일 초기화 기준 계산, 기록 검증
- `chat.js` — 채팅 송수신, 닉네임 보관, 접속자 수 집계
- `firestore.rules` — Firestore 보안 규칙
