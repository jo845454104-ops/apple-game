학생들이 실시간으로 플레이하고 있고, **하루 종일 조작·사칭·차단 우회 시도가 있었습니다.** 코드를 고칠 때 그 점을 전제해야 합니다.

### 2. 배포는 반드시 이 순서로

```bash
# 1) 코드 수정 후, 모든 모듈의 ?v=NN 을 한꺼번에 올린다 (아래 스크립트 참고)
# 2) 커밋 & 푸시
git add -A && git commit -m "..." && git push origin main
# 3) GitHub Pages 반영 확인 (10분 캐시가 있어 확인 필수)
curl -s https://jo845454104-ops.github.io/apple-game/ | grep "script.js?v="
```

버전 일괄 상향:

```bash
python3 -c "
for f in ['index.html','script.js','chat.js','leaderboard.js','firebase-app.js','profanity.js','fingerprint.js','firebase-config.js','roulette.js','event.js','duel.js','shop.js']:
    s=open(f,encoding='utf-8').read(); open(f,'w',encoding='utf-8').write(s.replace('?v=49','?v=50'))

```

> **왜 버전이 필요한가**: GitHub Pages는 파일을 10분간 캐시합니다. HTML만 새것이고 JS는 옛것인 상태가 되면 새 버튼이 눌리지 않는 등 이상 동작이 생깁니다. 실제로 겪었습니다. CSS도 마찬가지라 `style.css?v=` 를 씁니다.

보안 규칙 배포:

```bash
npx firebase-tools deploy --only firestore:rules --project jo8454-ea749
```

### 3. 규칙과 클라이언트는 항상 같이 움직여야 합니다

**두 번 사고가 났습니다.**

- 서버가 거부(permission-denied)한 것을 클라이언트가 "조작"으로 오인해 **정상 참가자를 자동 차단**했습니다. 지금은 물리적으로 불가능한 값일 때만 차단합니다.
- 차단 자동 해제를 클라이언트에만 넣고 규칙에 빠뜨려서, **화면상 풀린 사람이 실제로는 채팅을 못 썼습니다.**

규칙을 조일 때는 **클라이언트를 먼저 배포하고, 참가자들이 새 버전을 받은 뒤에 규칙을 조입니다.**

## 기능

### 게임
2분 제한. 드래그로 합 10 매칭. 다크모드, 그린애플 모드, 연한 색, BGM 지원. 모바일 세로·가로 레이아웃 대응.

### 채팅 · 접속자
닉네임은 **한 번 정하면 변경 불가**(자작극 방지). 브라우저에 저장돼 새로고침해도 유지됩니다. 접속자 수는 30초 신호를 15초마다 집계합니다. 실시간 리스너를 쓰면 읽기가 접속자 수의 제곱으로 늘어 무료 한도를 넘기 때문입니다.

### 룰렛 (100점 돌파)
식사권 0.01% / 커피 3% / 데이트권 5% / 딱밤 20% / 나머지 꽝. **하루 3회**, 닉네임당 제한.

### 돌발 이벤트
평일 14~17시 사이 하루 1~2회, 30분간. 목표 107~112점 달성 시 커피. **시작 30분 전에야 배너가 뜨고 시각은 알려주지 않습니다**(돌발이므로). 쉬는 시간(매시 50분~정각)과 겹치지 않게 정각~20분에만 시작합니다.

일정은 **날짜를 씨앗으로 계산**해서 서버 없이도 모든 참가자가 같은 이벤트를 봅니다.

### 개인 증정권 발급
자기 이름으로 커피권·데이트권·식사권을 발급합니다. **커피권 1인 1장, 데이트권 3일에 1장, 식사권 7일에 1장.**

일련번호가 곧 문서 ID입니다(`닉네임__종류__회차`). 같은 회차에 같은 종류를 두 번 만들 수 없어서 발급 주기가 서버에서 강제됩니다. 짧은 코드(`A3F9-2K`)로도 전산 확인이 가능합니다.

### 멀티플레이 대결
방을 만들면 시드가 정해지고 두 사람이 **완전히 같은 배치**로 겨룹니다. 비밀번호는 방장이 선택(비우면 공개방).

증정권은 목록에서 **눌러서 올리고 내리는 토글** 방식이고, 거래창처럼 양쪽이 올린 것을 서로 볼 수 있습니다. 여러 장 가능합니다.

대결 시작 전 **5초 카운트다운**이 돌아 양쪽이 같은 호흡으로 출발합니다. 끝나면 승리/패배/무승부 결과 화면이 뜨고 획득한 증정권이 표시됩니다. **진 쪽의 증정권은 이긴 쪽으로 자동 이전**됩니다.

**대결 중 나가면 기권 처리**되어 상대가 바로 이깁니다. 페이지를 닫아도 기권으로 잡힙니다.

## 부정행위 방지

### 서버 규칙이 막는 것 (`firestore.rules`)

클라이언트를 우회해 Firestore에 직접 써도 거부됩니다.

- 점수 0~170, `매칭×2 ≤ 점수 ≤ 매칭×3`, 사과당 최소 0.7초
- 등록 시각은 서버 시각만 (시각 위조 차단)
- 차단된 기기·지문의 모든 쓰기 거부
- 닉네임 금지어, 중복 닉네임
- **점수의 수정·삭제 전면 차단**
- 차단 목록 쓰기 전면 차단 (아래 참고)

### 리플레이 검증 — 가장 강력한 수단

보드를 시드로 만들고 매칭할 때마다 **시각과 지운 칸**을 기록합니다. **100점을 넘는 기록은 수순 검증을 통과해야 랭킹에 오릅니다.**

검사 항목: 지운 칸들의 합이 10인가 / 같은 칸을 두 번 지우지 않았나 / 매칭 간격이 사람 속도인가 / 수순으로 지운 수가 점수와 맞나.

검증에 걸려도 **게임 플레이 자체는 막지 않고 기록만 등록되지 않습니다.**

랭킹·기록실·관리자 창에서 🎬 버튼으로 재생해 확인할 수 있습니다.

### 실측 정상 범위 (조작 판단 기준)

- 매칭당 사과: **2.1~2.5개**
- 초당 사과: **0.86~0.99개**
- 플레이 시간: 대부분 120초를 꽉 채움

이 범위를 크게 벗어나면 의심입니다. 관리자 창의 점수 목록에서 빨간색으로 표시됩니다.

### 막을 수 없는 것 (정직하게)

- 개발자도구로 **물리적으로 가능한 범위의 그럴듯한 기록**을 만드는 것
- **다른 PC나 휴대폰**으로 접속 (차단은 기기+브라우저 지문 단위)
- 브라우저 밖(파이썬 등) 요청 → **App Check로만 차단 가능** (미설정, 아래 참고)
- 대결에서 두 사람이 짜고 한쪽이 일부러 지는 것

> 상위권 시상이 걸렸다면 **최종 순위는 현장 재플레이로 확인**하는 것을 권합니다.

### 절대 하지 말 것

- **하드웨어 지문으로 차단하지 마세요.** 같은 기종 PC끼리 겹쳐 실습실 전체가 막힙니다. 실제 사고가 났습니다.
- **차단 등록·점수 삭제 권한을 웹에 열지 마세요.** 접속자 목록에 기기 ID가 공개돼 있어서, 학생 한 명이 참가자 전원을 차단하거나 랭킹을 지울 수 있습니다. 이 구멍을 실제로 발견해 막았습니다.

## 운영자 도구

우측 하단 **접속자 칩**을 클릭 → 비밀번호 입력 (비밀번호는 `.admin-token` 파일, git에 올라가지 않음).

접속자 목록, 차단 목록(차단 중/해제됨 표시), 채팅 관리(개별·닉네임별·전체 삭제), 점수 관리(의심 표시·리플레이·삭제 명령 복사)를 쓸 수 있습니다.

인증 상태는 저장하지 않고 메모리에만 두며 창을 닫으면 해제됩니다. 비밀번호는 PBKDF2 20만 회 해시로만 코드에 있습니다.

> 개발자도구를 아는 사람은 여전히 인증을 건너뛰고 화면을 볼 수 있습니다. 다만 **파괴적 동작(점수 삭제·차단 등록)은 서버가 막고** 있어서 화면을 본다고 훼손할 수는 없습니다.

### 자주 쓰는 명령

```bash
# 점수 삭제
npx firebase-tools firestore:delete scores/<문서ID> --force --project jo8454-ea749

# 차단 해제 (매일 09시에 자동으로도 풀림)
npx firebase-tools firestore:delete blocked/<기기ID> --force --project jo8454-ea749

# 채팅 긴급 잠금: Firebase 콘솔에서 config/settings 문서의 chatLocked 를 true 로
# (웹에서 못 바꾸게 막아둠 — 열어두면 그 자체가 테러 수단이 되므로)
```

## 아직 안 한 것

**App Check (봇 차단)** — 파이썬 스크립트 같은 자동화는 브라우저를 거치지 않아 클라이언트 방어를 전부 건너뜁니다. App Check가 유일한 근본 대책이고 **코드는 이미 넣어뒀습니다.** `firebase-config.js`의 `recaptchaSiteKey` 만 채우면 켜집니다.

1. https://www.google.com/recaptcha/admin/create 에서 reCAPTCHA **v3** 등록, 도메인 `jo845454104-ops.github.io`
2. Firebase 콘솔 → App Check → 앱 등록 → reCAPTCHA v3 → 비밀 키 입력
3. **사이트 키를 코드에 넣고 배포한 뒤에** App Check의 Cloud Firestore 적용(Enforce)을 켜세요. 순서를 바꾸면 참가자 요청이 전부 거부됩니다.
